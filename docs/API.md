# REST API

Base URL: `http://localhost:8000/api/v1`. Interactive documentation is
generated by FastAPI at `/docs` (Swagger UI) and the machine-readable schema
at `/openapi.json`, from which the frontend's TypeScript types are generated.

## Conventions

- **Authentication:** every endpoint except `/health` requires the header
  `X-API-Key: <key>`. A missing or wrong key returns `401`.
- **Formats:** JSON in and out, except uploads (`multipart/form-data`) and
  file downloads. Money values are strings (`"1150.00"`) so no precision is
  lost; dates are ISO 8601 (`"2026-11-07"`).
- **Errors** use one shape:
  ```json
  {"error": {"code": "unsupported_format", "message": "File type text/html is not accepted", "details": {}}}
  ```
- **Pagination:** list endpoints take `page` (from 1) and `page_size`
  (default 25, maximum 100) and return `{"items": [...], "page": 1, "page_size": 25, "total": 213}`.
- **Rate limits:** uploads 30 requests a minute and search 120 a minute per key;
  `429` when exceeded.

| Status | Meaning |
|---|---|
| 200 / 201 / 202 | OK / created / accepted for background processing |
| 400 | Request is malformed |
| 401 | Missing or invalid API key |
| 404 | No such resource |
| 409 | Conflict, for example reprocessing a document that is still processing |
| 413 | File or request too large |
| 415 | File type not accepted |
| 422 | Validation error in the request body |
| 429 | Rate limit exceeded |

## Health

### `GET /health`
No authentication.
```json
{"status": "ok", "database": "ok", "redis": "ok", "llm": "ok", "version": "1.0.0"}
```
`status` is `degraded` if any dependency is down.

## Documents

### `POST /documents`
Upload one or more files. Returns immediately; processing runs in the
background.

Request: `multipart/form-data` with one or more `files` fields.
Limits: 20 files per request, 200 MB per file (configurable).

`202 Accepted`:
```json
{
  "accepted": [
    {"id": "6b1f...", "filename": "inv_0042.pdf", "status": "queued", "exact_duplicate_of": null},
    {"id": "9c3a...", "filename": "ledger.xlsx", "status": "queued", "exact_duplicate_of": "41d0..."}
  ],
  "rejected": [
    {"filename": "notes.docx", "code": "unsupported_format", "message": "Accepted formats: PDF, JPG, PNG, TIFF, XLSX, XLS, CSV"}
  ]
}
```
Files are checked one by one, so one bad file does not reject the batch. A
corrupted file in an accepted format is accepted here and fails during
processing, with the reason recorded.

### `GET /documents`
List documents. Filters: `status`, `format`, `uploaded_from`, `uploaded_to`.
```json
{"items": [{"id": "6b1f...", "filename": "inv_0042.pdf", "format": "pdf", "status": "processing",
            "stage": "ocr", "progress_done": 12, "progress_total": 40, "invoice_count": 0,
            "uploaded_at": "2026-11-10T09:12:03Z"}], "page": 1, "page_size": 25, "total": 1}
```

### `GET /documents/{id}`
Status, progress and a summary of what was found. This is the endpoint the
frontend polls.
```json
{
  "id": "6b1f...", "filename": "inv_0042.pdf", "format": "pdf", "size_bytes": 184233,
  "page_count": 2, "status": "needs_review", "stage": "done",
  "progress_done": 2, "progress_total": 2,
  "error": null,
  "pages": [{"page_number": 1, "kind": "scanned", "ocr_confidence": 87.4},
            {"page_number": 2, "kind": "scanned", "ocr_confidence": 52.1}],
  "invoices": [{"id": "a7e2...", "invoice_number": "INV-2026-00123", "total": "1150.00",
                "currency": "BDT", "review_status": "needs_review", "issue_count": 1}],
  "last_run": {"attempt": 1, "status": "succeeded", "stage_timings_ms": {"ingest": 31, "ocr": 2840, "extract": 1910, "post": 77}}
}
```
For a failed document, `error` is `{"code": "encrypted", "message": "PDF is password-protected"}`.

### `GET /documents/{id}/history`
All processing runs and their events, newest first.

### `GET /documents/{id}/file`
Download the original file, for the side-by-side review view.

### `GET /documents/{id}/pages/{n}/image`
Page `n` rendered as PNG (`?dpi=110` by default), for documents that are
not images already.

### `POST /documents/{id}/reprocess`
Run the document again. Body (optional):
```json
{"from_stage": "extract"}
```
`from_stage` is one of `ingest` (default), `ocr`, `extract`, `post`; earlier
results are reused. `202` with the new run; `409` if the document is
currently processing.

### `POST /documents/reprocess-failed`
Resubmit every document with status `failed`, or those listed:
```json
{"document_ids": ["6b1f...", "9c3a..."]}
```
`202`: `{"queued": 7}`.

## Invoices

### `GET /invoices`
List extracted invoices. Filters: `supplier` (partial, case-insensitive),
`customer`, `invoice_number`, `currency`, `date_from`, `date_to`,
`min_total`, `max_total`, `review_status`, `issue_code`, `document_id`.

### `GET /invoices/{id}`
The full structured result.
```json
{
  "id": "a7e2...", "document_id": "6b1f...", "pages": [1, 2],
  "invoice_number": "INV-2026-00123",
  "invoice_date": "2026-03-14",
  "supplier_name": "Padma Office Solutions",
  "customer_name": "Meghna Logistics",
  "subtotal": "1000.00", "tax": "150.00", "total": "1150.00",
  "currency": "BDT",
  "line_items": [
    {"position": 1, "description": "Laser Toner Cartridge", "quantity": "2", "unit_price": "500.00", "amount": "1000.00"}
  ],
  "extraction_method": "llm",
  "field_confidence": {"invoice_number": 0.97, "invoice_date": 0.62, "total": 0.95},
  "evidence": {"total": "Total (incl. VAT)   Tk 1,150.00"},
  "review_status": "needs_review",
  "issues": [
    {"id": "c01d...", "code": "low_confidence", "severity": "warning", "field": "invoice_date",
     "message": "Date 03/14/2026 read from a low-quality scan", "resolved": false}
  ],
  "group": null
}
```
A field that is not on the document is `null`. The API never fills it in.

### `PATCH /invoices/{id}`
Manual correction. Send only the fields that change; `line_items`, if
present, replaces the whole list.
```json
{
  "corrected_by": "Pretom",
  "fields": {"invoice_date": "2026-03-14", "total": "1150.00"},
  "line_items": null,
  "note": "Date checked against the original"
}
```
`200` with the updated invoice. Each changed value is recorded in the
correction history, validation runs again, and `extraction_method` becomes
`manual` for the corrected fields.

### `POST /invoices/{id}/review`
Mark as reviewed without changes.
```json
{"reviewed_by": "Pretom", "decision": "approve", "note": null}
```
`decision` is `approve` or `accept_with_issues`. `approve` returns `409` if
any error is unresolved. `accept_with_issues` records that a person checked
the errors (for example, a supplier's arithmetic mistake) and accepts the
invoice as printed; the reviewer, decision and note are stored on each
resolved issue.

### `GET /invoices/{id}/corrections`
The correction history for one invoice.

### `GET /invoices/export`
Same filters as `GET /invoices`; returns CSV (`?format=csv`) or JSON.

## Search

### `GET /search`
| Parameter | Meaning |
|---|---|
| `q` | Free text |
| `mode` | `keyword`, `semantic` or `hybrid` (default) |
| any `GET /invoices` filter | Applied in all modes |
| `limit` | Default 20, maximum 100 |

```json
{
  "mode": "hybrid", "query": "toner from Dhaka suppliers",
  "results": [
    {"invoice_id": "a7e2...", "supplier_name": "Padma Office Solutions", "invoice_number": "INV-2026-00123",
     "total": "1150.00", "currency": "BDT", "score": 0.031, "keyword_rank": 2, "semantic_rank": 1,
     "snippet": "... Laser <b>Toner</b> Cartridge ..."}
  ]
}
```

## Duplicates and cross-verification

### `GET /groups`
Invoices found in more than one document. Filters: `status`
(`consistent`, `mismatch`), `match_method`.

### `GET /groups/{id}`
Field-by-field comparison of the group's invoices.
```json
{
  "id": "e5b0...", "status": "mismatch", "match_method": "key",
  "members": [
    {"invoice_id": "a7e2...", "document": "inv_0042.pdf", "format": "pdf"},
    {"invoice_id": "f913...", "document": "march_ledger.xlsx", "format": "xlsx"}
  ],
  "comparison": [
    {"field": "total", "values": ["1150.00", "1265.00"], "match": false},
    {"field": "invoice_date", "values": ["2026-03-14", "2026-03-14"], "match": true}
  ]
}
```

### `POST /cross-verify`
Compare any two invoices on demand, for example when a PDF and a
spreadsheet record use different invoice numbers. Optionally saves them as a
group.
```json
{"invoice_ids": ["a7e2...", "f913..."], "save_group": true}
```

Counts used by the dashboard and the evaluation script.
```json
{
  "documents": {"total": 219, "completed": 172, "needs_review": 39, "failed": 8, "processing": 0},
  "invoices": {"total": 248, "auto_approved": 190, "needs_review": 58},
  "extraction_method": {"spreadsheet": 64, "rules": 120, "llm": 64},
  "avg_seconds_per_page": {"pdf_digital": 0.04, "pdf_scanned": 1.9, "jpg": 1.7}
}
```
The numbers above are illustrative only; measured values are in the
evaluation report.
